## 2. Actual root input and a useful exact width cancellation

The retained upstream input is lexicographic on
`[P0] x [2^K]^D_total x [S0]`, with r polynomial coefficients per address.
Components are signed w0-bit MSB-first, real then imaginary, on grid2^-p0.
The **separate descriptor tape** contains
`Gamma(p0,d,r,D_total,P0,S0,K,rho+1,w0)`.
Unit-disk entry, w0>=p0+2, w0=O(p0), O(p0) address/descriptor length and
superpolynomial record length r are actual source promises. Gamma6 is not
this nine-code descriptor. Bit rho is counted from the chunk's least
significant end; the native packed view has contiguous selected address bits.

Application §5 gives, after the Q0 reserved-axis processing,
`p*=p0+Q0`, `h*=Q0+1`, `D_root=D_total-Q0`.
Substituting into its common format yields exact conservative choices

`fractional_bits = p*+D_root = p0+D_total`,
`w* = p*+h*+2D_root+3 = p0+2D_total+4`,
`temporary_component_bits = w*+26`.

Numerical grid/width production thus need not wait for Q0: p0 and D_total
are already supplied. These widths stay fixed in every descendant. A child's
current active width cannot replace the original root dimension. The source
already proves this precision guard and the individual-kernel fallback;
the cancellation is an ABI specialization, not a new precision theorem.

A charged guard conversion reads each original signed numerator n and emits
`n*2^D_total` in w* bits. Unit-disk entry implies |n|<=2^p0, so it fits and
denotes the same value on grid2^-(p0+D_total). Redundant leading sign bits
can be removed if w0>w*. Include output, signed conversion, heads and cleanup:
`O(V_in+V_guard+E_root)`, with V_in=2Mrw0 and V_guard=2Mrw*.
Binary addition/Gamma encoding of w* takes O(E_root+log(w*+1)) work, without
expanding p0 just to decode its value. Both widths are Theta(p0), giving a
linear complete-field guard conversion on the admitted family. No literal
guard graph is emitted here. The fractional grid remains an external typed
context because Gamma6 does not encode it.

## 4. DATA-only homes and the complete optimistic bill

B1 permits binary bodies of common extent F_HOME, including a contract
explicitly identifying all-zero storage as semantic zero. The source input
already separates descriptor from DATA. Thus keep `F_HOME=v`, and hold the
shared root descriptor, current ROW grant, occurrence/view and chart/liveness
state in separate charged control storage. On that typed domain0^v is the
actual zero scientific array for INIT1526 in chart601. This constructs no
shared descriptor and earns no owned productive credit. In the earlier
combined ABI0^(E+v) remains an invalid Gamma6 packet; there is no conflict.

A needed native wrapper would gather DATA with B1; produce the exact private
Gamma6 HEADER; pack DATA into a distinct owner; execute the frozen31-tape
core; inverse-pack; return exactly v bits to the original operand; and
retire every header/private bank. The native core already separates HEADER
and DATA. Changing E affects work, never HOME extent. The published combined
HOME adapter is not this wrapper. Its permanent-origin/guard rules must be
reproved for the new entry. The inline-header signed ADD graph would need
its corresponding DATA-only wrapper as well.

For comparison, an explicit simple packing schedule moves the9f named bits
to the front in reverse desired order, using stable two-bucket record passes
within each P0*R_j prefix. Concatenate zero/one buckets, preserving each
complete polynomial record and the relative order of other address bits.
Reverse the passes on return. Each pass copies payload O(1) times, returns
heads and retires its buckets. Conservatively charge polynomial work in the
actual A=O(p0) descriptor/address length per record. The source's complete
length-r records pay that work eventually. The resulting optimistic bill is

`T_pack+T_unpack = O(f*v + poly(A) + E_root + E_native)`.

It is linear for a fixed compile-time f<=q. Input-varying f is not a free
finite-template constant. For large f this schedule supplies no selected
accelerated nonleaf tariff. No new packing table or faster mechanism is
implemented. Whole-unit normalizers and their inverse returns keep their
own separately priced contracts. Classical stable partition is not claimed
as novel or as a tested tape graph here.

The local successful invoice includes

`T_descriptor + T_pack + T_core + T_unpack + T_header_retire`
` + T_whole_unit_routes + T_B1_delivery`,

where actual rank-two `T_core<=2^24(f*v+E_native+1)`. Add the root guard
conversion, reservation, INIT/CLEAR and all other source events separately.
For n_svc services, K_home homes and b operand tapes, B1 still pays
`16(n_svc+1)(K_home+b+1)(v+2)` plus services. If node productive volume is
V_node and its W roles have v=V_node/W, this retains that normalization.

Next-depth role fields have R_(j+1)=R_j/W and v/W DATA bits, with the same
L,r,w* and complete root factor. The child uses its own extent; the parent's
v cells and live banks remain parked. There is no claim that the child and
parent extents are equal, or that every return scans all ancestors. Retained
history is entry history plus actually visited DATA/header/descriptor banks
and the native-core increment. A local conservative increment is
O(v+E_native+poly(A)) plus that core increment; suspension additionally keeps
all actual parent frames. Erasure never refunds previously larger backing.
