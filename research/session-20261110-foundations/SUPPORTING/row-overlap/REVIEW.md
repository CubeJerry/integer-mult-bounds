# Novelty correction for coded whole-row services

## Decision

**Publication as a new research contribution is withheld.** Preserve the valid
finite graph, proof, exact bills and independent checks as a validation/control
variant. Do not list this package as foundational-assumption progress or as
closing previously missing Controller row callbacks.

The prior bounded overlap audit missed an earlier, stronger dispatcher because
it is retained in the canonical tree through nested vendor exports. This is a
novelty correction, not a discovered error in the new graph's scoped theorem.

## What already exists

Predecessor PROOF §§1–4 give an all-size theorem for any fixed final template
rank, productive width and field list. They specify the same seven-symbol
physical alphabet and three-bit numerical encoding, a 23-value binary
descriptor, arbitrary fixed row divisors, complete row/stock quotients and
actual ordinary geometry/cutoff updates.

Its recovered services.py implements all four actual callbacks. is_leaf runs
the encoded cutoff table or a separately declared fixture predicate; prepare
emits the child header; install splits all complete rows, installs that header
and invokes the separately admitted remainder service; collect merges every
ordered public output. PROOF §7 and check_join.py join these to the real
Controller and Stack, including protected output before pop and occupied-owner
replacement. The reported source-generated fixture has 72 ordinary children,
512 leaves and warm reentry, plus a separate physical ordinary-width example.

The predecessor produces its unary guides with amortized linear cost, preserves
outer-prefix and within-row factors separately, distinguishes matched compiler
occurrences from ordinary row descent, and supplies canonical pattern padding.
Section 6 already describes producing a zero row by a charged complete-row
shape copy and owned initialization, with both scans charged. The broader
selected root-parameter producer remains explicitly open.

## Differential controls

The independent differential script runs both actual tables on five small
physical inputs. The predecessor header prescribes one row per child; the new
guide specifies the same twelve-bit, two-component row.

| Input | Predecessor | Guide variant |
| --- | --- | --- |
| Correct fields | Accept | Accept |
| Same length, lost component separator | Accept | Reject |
| Same length, virtual blank code100 | Accept | Reject |
| Extra complete row in every field | Reject | Accept |
| Extra complete row only in last field | Reject | Reject |

Malformed component cases violate the predecessor's stated numerical-provider
premise; their acceptance is not a predecessor bug. Uniformly extra rows
violate the guide variant's intended inherited row-count premise. The latter
case establishes that the variant is not a general strengthening of return
validation. Both implementations reject asymmetric extra rows.

The script uses a separately written physical Tape and header encoder. Both
normal and optimized runs print `PASS_ROW_OVERLAP_DIFFERENTIAL 5`.
DIFFERENTIAL.json records exact acceptance and partial output evidence. This
is a novelty/domain comparison, not a full replay of either author's suite.
