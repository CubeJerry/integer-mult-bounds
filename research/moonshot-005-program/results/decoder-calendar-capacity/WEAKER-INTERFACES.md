# Which decoder requirements still exceed the target budget?

**Proved source-calendar information lower bounds. No new kappa.** This refines
PROOF.md using its scalar field, independent input blocks, arbitrary payloads,
free immutable caches and fixed funded arrival calendar. The original common
execution must still be cochart-decodable after every source event. Only the
required second-minus-first observations are weakened.

The calendar lemma applies to any specified required rows and times. Insert a
difference row into historical knowledge only when its interface requests it.
Source ADDs may now create new main requirements because helper differences
need not be decoded. A main departure requirement is evaluated in its source
chart BEFORE that MOVE's funded destination arrivals. All final main rows are
required at the endpoint. These ordering conventions are essential.

`weaker_demands.py` computes the last three rows over Q. Independent modular
replay verifies every demand innovation and chart maximum, checking that all
source denominators are invertible. A nonzero minor modulo that prime witnesses
the corresponding rational rank lower bound. These finite-source certificates
support the dimension theorem for every admitted complete-field size.

For the departure interface, 104 charts have a positive maximum: charts 90 and
98 have two each, the other 102 one each. The total 106 exceeds the unchanged
H4 allowance of at most 98 extra positive-rank arrivals. Always constructing the
virtual main difference before each funded main MOVE therefore cannot meet that
budget under this common-state contract and calendar, even with ideal helper
coding and unlimited memory. Since both owned calendars give 106, monotonicity
also gives 106 for EVERY mixed choice of one or two channels per owned MOVE,
including the ten-owned-skip profile. No extra replay is needed for that corollary.

This is stronger than failure of the observation graph with 2879 extra
full-horizon routes. That graph may be substantially improved and still fail
if it retains universal main-departure decoding. A changed physical code does
not help if the same virtual departure row is nevertheless reconstructed.

Removing one scalar-row demand can reduce historical rank by at most one, in
its single chart. Hence at least eight units of departure-demand rank must be
relaxed to reduce 106 to 98, with everything else fixed. This does not say that
deleting any eight demands suffices or that useful deletions are constructed.
For the ten-owned-skip profile's remaining seven-arrival ceiling, the analogous
necessary reduction is 99. New savings or changes to targets or the calendar
require a fresh calculation.

## Remaining directions

The endpoint-only zero means this generous relaxation supplies no rank
obstruction. It is NOT feasibility: arbitrary teleport payloads are granted,
source-side acquisition is ignored, and ordinary work, memory and precision
are unpriced. Actual transport may still be impossible or too expensive.

Two escape mechanisms remain in this programme: carry coded main rows without
reconstructing each intermediate virtual departure; or defer unused COMMON
helper values too, restoring them before their actual source reads. The latter
leaves the common-all-live premise, as a quiet-interval route loan illustrates.

Both retain the final native contract: independent main inputs, arbitrary
helpers, all required endpoints, ownership, restoration and physical costs.
These results remove inadequate intermediate interfaces, not theorem acceptance
criteria. All five foundational assumptions remain unresolved. Prepared for
